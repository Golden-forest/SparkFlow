## 已确认方案

保留现有 React/Vite 前端和 Cloudflare 静态托管。新增独立 Node.js/TypeScript 服务，使用 Better Auth 实现个人注册、登录、邮箱确认、密码恢复和数据库会话，PostgreSQL 保存账户及用户数据，沿用 Caddy 提供 HTTPS 反向代理。业务模块通过统一账户模块访问会话；复制到新项目时复用模块与配置，不默认让所有项目共用生产用户数据库或共享登录状态。

Better Auth 官方支持 [React 客户端与数据库接入](https://better-auth.com/docs/installation)、[独立 Node 服务](https://better-auth.com/docs/integrations/express)以及[邮箱与密码流程](https://better-auth.com/docs/authentication/email-password)。它提供[会话撤销、来源检查和限流](https://better-auth.com/docs/reference/security)；仍需正确配置并验证。验证码和密码恢复必须接入真实发信服务，不以控制台打印链接替代生产邮件。

与完整 Supabase 栈相比，新增一个账户服务及数据库的组件更少，预计更适合这台共享主机；**这是架构推断，不是内存占用保证**。完整 Supabase 自托管的官方最低配置为 2 核/4 GB/40 GB SSD，推荐 4 核/8 GB+/80 GB+ SSD。现有 60 GB 总磁盘低于推荐值，而且剩余空间未知，因此不默认安装完整栈。参见[资源要求](https://supabase.com/docs/guides/self-hosting/docker)与[自行负责的维护事项](https://supabase.com/docs/guides/self-hosting)。

部署边界：独立系统用户、服务目录、systemd 服务和数据库角色；账户 API 与 PostgreSQL 只监听本机。为新服务增加 Caddy 站点，保留 CameraAI 原有站点。数据库不开放公网端口，不复用 CameraAI 管理员口令或云服务密钥。使用版本化迁移，并在启用真实账户前验证异机备份与恢复。单台服务器不提供高可用；未来容量升级由实际指标驱动。

## 域名与资源安排

候选布局是账户前端 `lab.heyflint.cn`，账户 API `lab-api.heyflint.cn`，课件 HTML 在独立 Cloudflare 资源项目。域名只是拟议用途，未验证解析、证书或备案适用情况，未执行任何配置。

前端与 API 使用 HTTPS 且位于同一站点下，避免把 `pages.dev` 前端直接连接到另一站点的 Cookie 账户后台而依赖第三方 Cookie。跨源请求显式携带凭据；服务端只允许准确的前端来源，不使用通配来源。会话 Cookie 保持 API 主机专属、HttpOnly、Secure、SameSite=Lax、Path=/，不开启父域共享。生产允许来源不包含开发域名或课件源。

现有 `/courseware/`、`/simcanvas/`、`/rating/` HTML 的直接访问仍与应用同源。接入账户前，把可执行课件迁移到独立资源部署，并验证课件加载、预览 sandbox、下载和直接打开。账户前端不继续托管任意上传 HTML；不会把资源源加入账户 API 的可信来源。旧站点与新站点的链接、资源清单、共享授权码语义需要一起检查。

目前共享授权码保护整个站点，也包括课件与评分文件。迁移默认保留访问限制，不能因独立部署把这些文件变成公开资源。现有中间件不能直接复制为跨源资源保护方案：`X-Frame-Options: SAMEORIGIN` 会阻止新前端嵌入资源，跨站 iframe 也不能依赖 SameSite=Lax 授权码 Cookie。实施时需确定资源访问机制及精确的 CSP `frame-ancestors`；可以使用同站点的独立资源子域保留 Cookie 条件，但资源访问权限仍需单独验证。不要放宽账户 API 可信来源或 Cookie 域来解决资源加载。

账户 API 主机专属 Cookie 不会发送给前端 Pages，因此不能拿它直接替换现有静态站点门禁。需明确共享码门禁是否继续作为独立站点限制；个人账户权限在 API 执行。移除共享码或公开资源均不作为当前方案的默认行为。

本地资料截至 2026-10-02 仍记录备案审核中，当前结果未知。腾讯云[官方说明](https://cloud.tencent.cn/document/product/243/18910)明确指出，中国内地服务器通过域名或仅通过 IP 提供非经营性网站服务均涉及 ICP 备案；不能把“IP + 非标准端口”作为上线绕过备案的依据。此项在正式上线前核实。
